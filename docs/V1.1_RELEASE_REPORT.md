# Chiang Mai Air Watch V1.1 release report

## 1. Scope

V1.0 was upgraded in place to a backward-compatible multi-provider architecture. Ping, DNS, TLS, Apache, server-global configuration and system Node 18 were not changed.

## 2. Mission package

`CODEX_MISSION_AIR_ABERG_V1_1_DUSTBOY.zip` was unpacked into `docs/CODEX_MISSION_AIR_ABERG_V1_1/`; all ten mission/source files were reviewed in their prescribed order.

## 3. Pre-change protection

Code and database backups were created before implementation. A separate post-migration database backup was restored into a disposable database and verified.

## 4. Architecture

The V1.1 provider factory and collector support `providers.observations` while preserving the V1.0 `providers.observation` fallback. Provider attempts, health and failures are isolated; official risk reconciliation still runs after provider attempts.

## 5. Database and retention

Migrations `002_multi_provider_history` and `003_weather_state` add daily summaries, the DustBoy request ledger and weather state. The fresh schema includes them. Existing measurement identity, deduplication and revision handling remain unchanged. Raw measurements retain 24 months by default, summaries ten years, and operational/request data use external-config intervals.

## 6. Air4Thai

Air4Thai remains the sole source for TH AQI, official area status, category transitions, alert incidents and push. The explicit `35t`/`36t` allowlist and strict TLS issuer bundle remain in use.

## 7. DustBoy

The adapter, canonical installation IDs, selected-station sync, geographic cap, hourly due check, rolling request ledger, latest/history normalization, resumable backfill, summary rebuild and provider health are implemented. DustBoy is always supplementary and AQI-null unless a future verified official-scale field exists.

## 8. Weather context

Open-Meteo Forecast current weather is collected server-side every 15 minutes into `weather_state`. Temperature, wind speed/direction/gust and precipitation are presented as context, never as a causal explanation.

## 9. History

The API supports raw `24h`/`72h`, 3-hour `7d`, 12-hour `30d`, daily `90d`/`1y`, and sample-weighted ISO-weekly `5y` data. Missing pollutant values remain null.

## 10. API and health

Station responses carry localized source/classification metadata. Current data includes a one-query local sensor summary and nullable weather. Health separates official and supplementary timestamps and reports enabled supplementary/weather degradation without hiding cached air data.

## 11. UI, map and PWA

Official status remains first. Provider-aware home/detail layouts, local median summary with separate valid-reading count, All/Official/Local filters, diamond/circle markers, PM2.5 display bands, lazy Leaflet initialization, validated map persistence and a V1.1 offline timestamp were added. The shell cache is `chiang-mai-air-watch-shell-v1.1.1`.

## 12. Security

The external config remains `root:www-data 0640`; no credential was added to the repository or logs. Public endpoints read MariaDB only, expose normalized values only, and retain `no-store`, CSP/HSTS and same-origin push protections. Runtime database grants remain DML-only.

## 13. Tests

Unit, isolated MariaDB integration, local/production Playwright+axe, Air4Thai/Open-Meteo live smoke, syntax, dependency audit, migration replay, backup restore, headers/private-path checks and Air production smoke passed. The final read-only Ping regression returned HTTP 200 for homepage, status and health; no Ping component was changed. Detailed counts are in `TEST_REPORT.md`.

## 14. Production and rollback

V1.1 code, migrations, asset version, Air-specific cron, Air4Thai, forecast, weather, summaries and retention are active with health HTTP 200. A fast rollback switches observations to Air4Thai only and disables DustBoy/weather; a full rollback uses the Air-only backup and never touches Ping.

Release artifact: `/var/backups/chiang-mai-air-watch/chiang-mai-air-watch-v1.1.2-20260905.tar.gz`; verify it with the adjacent `.sha256` file. The prior V1.1.0 artifact remains available only as a superseded rollback point.

## 15. Operator/device work and remaining provider history

DustBoy authentication, selected-station schema, reviewed sync/apply, latest collection, API/UI display and four of six 5y backfills are verified live. The `5263`/`5264` archive completion and separate 30d/1y schema smoke remain pending due CMU timeout/authorization and the rolling request window. Android push, iPhone installed-PWA push and physical Home Screen installation were completed and confirmed by the operator on 2026-09-05.
